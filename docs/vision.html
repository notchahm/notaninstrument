Notaninstrument · project vision

A MIDI controller is an instrument without an instrument.

Plug one in and you get silence until a computer joins the conversation. Notaninstrument is the small module that finishes the sentence: real multi-sampled sound, standalone, the moment you plug in — no DAW, no laptop, no waiting.

Why

The AKAI MPK Mini Play proved the gap instead of closing it.

It's portable, it's instant-on, and its built-in synth is a toy — welded to that one controller, with no way to give it better sounds. The actual want is modularity: swap controllers without touching the sound, swap sounds without touching the controller. Two other real products get closer to that (see "Prior art" below) — but none of them get all the way there, which is why three boards were weighed to build one anyway.

Prior art

What this becomes

Six rungs, each reusing what the one below it already built.

Not a feature list bolted together after the fact — every later rung leans on a mechanism the earlier one had to get right anyway.

  1. 1

    Core instrument

    Any class-compliant USB-MIDI controller in, a real multi-sampled instrument out — polyphonic, standalone, instant-on. Salamander Grand Piano is the first instrument built, not the ceiling on what this plays.

    CLAUDE.md
  2. 2

    Multi-instrument soundbanks

    A real instrument library, not just piano — drums, guitar, strings, whatever else gets converted — swappable at runtime via Program Change, from an SD library of .nib soundbanks.

    docs/multi-instrument-soundbanks.md
  3. 3

    DSP effects chain

    EQ, delay, compression, chorus, reverb on the mixed output. The difference between "plays samples" and "sounds like an instrument."

    docs/dsp-effects-chain.md
  4. 4

    Recording & looping

    EP-133-style layered looping, run standalone from a second USB-MIDI controller acting as a transport surface — the same multi-device host support rung 1 already needed, generalized.

    docs/recording-and-looping.md
  5. 5

    Dynamic sampling

    Record a real sound on the device itself — a guitar pluck, a voice, anything into the same input rung 4 already needs — and play it back chromatically as a new instrument, no computer. Comes out as the same .nib format rung 2 already routes.

    docs/dynamic-sampling.md
  6. 6

    Dongle / dock modularity

    The literal answer to the original itch: a self-powered dongle that also seats into a dock with an amp, real speakers, and physical controls — one brain, never two firmwares.

    docs/dongle-dock-architecture.md

Where things actually stand

Bring-up step 2 of 8: is USB-MIDI host even viable on this chip?

2 / 8

Arduino-ESP32 + Adafruit TinyUSB

Dead end

Confirmed by reading the installed toolchain's source, not by guessing: ESP32 host mode is hardcoded to an external MAX3421E chip that isn't in this project's BOM. Can't reach the board's native USB-A ports.

Raw ESP-IDF + vendored TinyUSB host

Builds clean · untested

Compiles end to end with the real host controller driver and MIDI class included — 216 KB binary, zero undefined references. Not yet flashed to real hardware.

Platform bet: stay on P4

Reconfirmed

Explicitly re-examined against falling back to the proven RP2350 path, and kept — the soundbank ceiling in "Why" above is the reason, not inertia.

What's next

The next unknown needs a soldering iron, not a keyboard.

  1. Flash real hardware. ESP32-P4 board, a class-compliant USB-MIDI controller, firmware/spike-usb-midi-idf — confirm tuh_midi_mount_cb actually fires on connect.
  2. If it fires: continue the bring-up plan in order — display, audio output, soundbank pipeline, single-voice integration, polyphony.
  3. If it doesn't: fall back to a hand-written MIDI class driver on ESP-IDF's native USB Host Library. A longer step 2, not a dead project.
